# Установка и запуск Android-версии

Предварительная сборка: непрерывный реальный AUTO ещё не принят. Перед передачей
заказчику прочитайте `RELEASE_STATUS.md`; commit и проверки указаны в `BUILD_INFO.json`
внутри ZIP. Виртуальное окружение, ADB и веса модели в ZIP не включены.
Windows transport и ветка main не меняются.

## Рабочая папка и окружение

Используйте рабочую копию `tiktok-live-automation`, ветку `feature/unified-transports`.
Папка `Documents\ChatGPT\tiktok-live-automation` на текущей VM пуста и не содержит проекта.
Фактическая копия: `C:\Users\Tiktok\Documents\tiktok-live-automation`.

Для новой установки нужны Python 3.12+, Git, Android platform-tools; для локальной
модели — запущенный совместимый сервер на разрешённом loopback endpoint профиля.
Существующую исправную `.venv` пересоздавать не требуется.

```powershell
Set-Location -LiteralPath 'C:\Users\Tiktok\Documents\tiktok-live-automation'
# Только если окружение ещё не создано:
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -m pip check
```

Для воспроизводимых версий этой сборки сначала выполните
`.\.venv\Scripts\python.exe -m pip install -r requirements-release.txt`, затем
`.\.venv\Scripts\python.exe -m pip install -e .`.
На новой установке скопируйте `config/examples/android-release.yaml` в
`config/operator.local.yaml` и укажите свой точный аккаунт в панели через Save/Apply.
На существующей установке сохраняйте свой overlay и папку `data`; пример поверх
личной конфигурации не копируйте. Пример не содержит личного @handle или секретов.

Локальный `.env` не входит в Git или ZIP. Безопасные исходные настройки:

```dotenv
LIVE_MODE=fake
ADMIN_LIVE_ENABLED=false
ENABLE_PHYSICAL_TIKTOK_SEND=false
ENABLE_PHYSICAL_WINDOWS_SEND=false
ADB_EXECUTABLE=C:/Android/platform-tools/adb.exe
```

Укажите существующий путь к ADB. Для VM настройте передачу USB телефона в гостевую
Windows. Проверяется только ранее reviewed Xiaomi M2101K9G / Android 13 / TikTok
You 46.8.3 на ожидаемом устройстве. Не подменяйте профиль для другого телефона.

Запустите локальный ADB-сервер и проверьте подключение. Эти команды не вводят текст:

```powershell
& 'C:\Android\platform-tools\adb.exe' -P 5037 start-server
& 'C:\Android\platform-tools\adb.exe' -H 127.0.0.1 -P 5037 devices -l
```

На этой VM модель `qwen/qwen3-8b` уже скачана. Для запуска внутри VM используйте
LM Studio или установленный CLI. При виртуальном видеоадаптере загрузите модель
на CPU; запуск сервера не выполняет генерацию и не начинает отправку:

```powershell
lms load qwen/qwen3-8b --gpu off --context-length 4096 --parallel 1 --identifier qwen/qwen3-8b --yes
lms server start --port 1234 --bind 127.0.0.1
```

Запуск локальной панели с выключенными физическими gates:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/ui`. Сама загрузка панели не начинает эфир,
не вводит текст и не включает автоматическую отправку. Проверьте активный режим
Android. Модель ИИ должна быть доступна внутри VM на loopback адресе профиля;
сервер, запущенный только на другом компьютере, автоматически доступен не станет.

Для SwiftKey один раз отключите в **Typing / Ввод** параметры **Autocorrect**,
**Quick prediction insert** и **Auto space**. На проверявшемся телефоне оператор
наблюдал замену `We're` на `Where` и лишний пробел при вводе через обычное поле.
Параметры описаны в [справке Microsoft по автокоррекции](https://support.microsoft.com/en-us/swiftkey-keyboard/how-does-the-spacebar-work-with-autocorrect-in-microsoft-swiftkey-keyboard)
и [пробелу после пунктуации](https://support.microsoft.com/en-us/swiftkey-keyboard/how-do-i-turn-off-autospace-after-punctuation-in-microsoft-swiftkey-keyboard).
Эта настройка не заменяет точную проверку поля: программа отправляет только текст,
совпавший с утверждённым ответом. Изменённое слово не считается успешным вводом.

## Ежедневный порядок

1. До эфира настройте тему, инструкции и локальную модель в профиле. При необходимости
   добавьте TXT/MD знания. Сохраните и примените настройки при отключённом чате.
2. Откройте собственный профиль в TikTok до эфира и нажмите **Подготовить и проверить**.
   Программа сама проверит точный @handle, элементы собственного профиля, устройство,
   установку, модель и журнал. Переписывать или отправлять проверочную фразу не нужно.
   Затем запустите собственный эфир самостоятельно и подключите чат своего аккаунта.
   Свежая проверка экрана ведущего автоматически связывает профиль с этим подключением SDK.
3. Пройдите существующий ручной допуск отправки и явное подтверждение Send control.
   Действительная привязка переиспользуется; перезапуск backend, переподключение, смена установки,
   аккаунта или применение настроек требуют соответствующей новой проверки.
4. Блок **Проверка готовности** показывает состояние устройства,
   версии, аккаунта, собственного эфира, SDK, модели, конфигурации и журнала,
   затем точный следующий шаг. Дополнительные проверки спрятаны в раскрывающемся блоке.
   Эта кнопка не подтверждает неизвестные операции,
   не вводит текст и не включает AUTO.
5. Только после отдельного разрешения на физический тест оператор включает
   разрешённый startup gate и явно включает AUTO в панели. Проверки перед каждой
   физической отправкой выполняются кодом автоматически. Перед каждым periodic
   нажимать «Проверить устройство» не нужно.

Наличие модели в списке не доказывает качество генерации. Смотрите оригинал,
перевод и подготовленные ответы во время ручной проверки.

## Периодические сообщения

Используются тема и periodic instruction применённого профиля. PERIODIC выдаёт
одно короткое нейтральное английское ASCII-утверждение: без вопросов, приглашений,
выдуманных событий, отзывов зрителей и финансовых гарантий. VIEWER_REPLY сохраняет
свои правила и может содержать уместные вопросы. Старые вопросительные шаблоны
нужно заменить через Save/Apply; они не получат право отправки.

Production: `interval_seconds=300`, `jitter_seconds=30`, `max_per_hour=12`.
Для отдельно разрешённого короткого теста настройте через существующие Save/Apply
`interval_seconds=60`, `jitter_seconds=0`, `mode=templates`. Для первой версии
оставьте templates; ответы ИИ на реальные комментарии зрителей работают отдельно.
Предусмотрены три точных нейтральных шаблона без апострофов и пунктуации:
`Welcome to the live stream`, `We are sharing useful ideas today`,
`Thanks for spending time with us`. Для остальных генерируемых periodic-текстов
действует строгая политика одного нейтрального утверждения.
Лимит `max_per_hour` остаётся действующим. Не удаляйте историю слотов, не очищайте
базы и не повторяйте старые сообщения ради ускорения. После успешного теста
верните production значения до начала следующего эфира.

## Если отправка остановилась

- **Отправка не выполнялась**: программа имеет доказательство, что до вызова Send
  не дошла. Старый ID остаётся consumed. В continuous AUTO технический REJECTED
  разрешает только будущие новые события после свежей проверки прежней привязки.
  Очередь старых событий отбрасывается; старая попытка не повторяется.
- **Отправка подтверждена**: есть подтверждающее SDK/UI доказательство.
- **Неизвестно, отправилось ли сообщение**: STOP. Самостоятельно проверьте чат.
  Действие **Я проверил чат. Разрешить новые сообщения** требует подтверждения,
  оставляет старую операцию UNKNOWN/consumed и разрешает лишь новые события.
  Оно не включает AUTO. Автоматического ACK UNKNOWN нет.

Одноразовый лимит отправки не восстанавливается после REJECTED. Смена сессии,
устройства, установки, отказ записи доказательства или незавершённая операция
исключают автоматическое восстановление.

В JSONL диагностике ввода сохраняются только длины, индекс/число несовпадений,
категории символов, exact/trim/casefold и результат команды. Текст ответа и
readback-текст в новые диагностические поля не записываются. Несовпадение не
принимается за успешный ввод и не разрешает Send.
При отказе свежей проверки после ввода отдельно записываются классификация экрана,
причина проверки и возраст предыдущего допуска LIVE. Если свежий снимок содержит
поле, сохраняется и результат сравнения без текста. Это диагностические данные;
истёкший допуск не разрешает дальнейший ввод или Send.

## Финальная приёмка и ZIP

Реальные действия требуют отдельного разрешения оператора. После обязательного
допуска выполните два НОВЫХ periodic-сообщения через существующий AUTO. Для каждого
нужен `sdk_echo_confirmed`; после первого continuous AUTO остаётся включённым.
При первой неоднозначности остановитесь без повтора. Запуск, подготовка и ручные
подтверждения не заменяются тестовыми флагами или поддельным receipt.

После теста вернуть production интервал. Для этой предварительной сборки выполнены
офлайн-проверки; их фактические результаты находятся в `BUILD_INFO.json`.
Не включать `.env`, `.venv`, пользовательские базы/слоты/журналы, captures, cookies,
ключи, локальные знания и личные профили. Пока эти условия не выполнены, версия
не объявляется готовой к передаче заказчику.

## Включение автоответов и остановка

После действительного допуска оператор сам включает **Автоответы / AUTOMATIC**.
Переключатель **Включить автосообщения** включает periodic-планировщик, но не AUTO:
при выключенном AUTOMATIC физических отправок нет. Действительная проверенная
привязка переиспользуется; новый runtime не наследует ручной допуск отправки.
Если допуск отсутствует, эта предварительная версия блокирует включение AUTO.
Нельзя восстанавливать его поддельным флагом или удалением базы.

Startup SEND gate по умолчанию выключен. Если планируется физическая работа,
после явного решения оператора запустите backend с разрешением Android SEND
до подготовки и проверки допуска, в этом окне PowerShell:

```powershell
$env:ENABLE_PHYSICAL_TIKTOK_SEND='true'
$env:ENABLE_PHYSICAL_WINDOWS_SEND='false'
$env:ADMIN_LIVE_ENABLED='false'
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Эта команда сама не включает AUTOMATIC и не запускает LIVE. Не используйте её
для чистого smoke; `.env` оставляйте с false. Для остановки выключите **Автоответы**,
дождитесь окончания текущей операции, отключите чат кнопкой панели и завершите
backend через Ctrl+C в его терминале. Эфир завершает оператор на телефоне.
Если результат UNKNOWN — проверьте чат и используйте только существующее явное
восстановление для будущих сообщений. Старую отправку не повторяйте.

Чтобы остановить сервер модели без GUI: `lms server stop`.
Перед следующим безопасным запуском установите
`$env:ENABLE_PHYSICAL_TIKTOK_SEND='false'`.

## Резервное копирование и обновление

Выключите AUTO, отключите чат и полностью остановите backend. Только после этого
архивируйте `data` целиком (включая SQLite WAL/SHM, если они остались), свой
`config/operator.local.yaml` и `.env`. Журналы dedup нельзя удалять или заменять
пустыми базами. Пример команды из рабочей папки, без отправки копии куда-либо:

```powershell
$backupFolder = Join-Path $env:USERPROFILE 'Documents\TikTok-private-backups'
New-Item -ItemType Directory -Path $backupFolder -Force | Out-Null
$backupItems = @('data','config/operator.local.yaml','.env') | Where-Object { Test-Path -LiteralPath $_ }
$backupPath = Join-Path $backupFolder ('private-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.zip')
Compress-Archive -LiteralPath $backupItems -DestinationPath $backupPath
```

Это личная резервная копия, она может содержать секреты и тексты базы знаний:
храните её отдельно, не включайте в релиз и не публикуйте. Релизный ZIP распакуйте
в новую папку, установите зависимости и перенесите свой overlay, `.env` и `data`
из остановленного экземпляра с сохранением структуры. Хранилище знаний связано
с `data`; отдельные исходные TXT/MD знания также сохраняйте в личной копии.
Не запускайте одновременно два backend с одним устройством или общими базами.
После восстановления runtime trust проверяется заново; резервная копия не включает AUTO.
